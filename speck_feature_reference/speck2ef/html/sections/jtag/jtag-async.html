11.6. JTAG Asynchronous I/O Operation

The Speck2e JTAG interface enables sending and receiving asynchronous events from the chip. The JTAG effectively provides an alternative to the Asynchronous I/O interfaces for AER communication for testing purposes.

Due to the nature of the JTAG serial protocol, however, asynchronous events can only be sent or received from the chip using a polling operation. Specifically, since no chip_ready or data_ready signal is present, the user must provide a value and read back the internal acknowledge signal from the chip by continuously reading a specific data register of the JTAG interface.

The following sections provide a detailed description of the asynchronous I/O protocol via JTAG.

11.6.1. Sending Asynchronous Events via JTAG

This operation is equivalent to sending a single asynchronous event via the chip Async Input Serial Interface

The Async input data bus is 32 bit wide in Speck2e.

send_ir(ASYNC_INPUT_ACK, 0x20, 8 bits)
ack_state = 0b00
# Check ACK internal state until ack is received:
while ack_state == 0b00:
   ack_state = send_dr(0b00, 2 bits)  # Receive 2 bits giving the ACK status information

send_ir(ASYNC_INPUT, 0x22, 8 bits)
send_dr(data[31:0], 32 bits)  # Async input message data

If a new message has to be sent in, the operation can be immediately repeated. Otherwise, the JTAG TAP Controller can be put back into RESET state.

11.6.2. Receiving Asynchronous Events via JTAG

This operation is equivalent to receiving a single asynchronous event via the chip from channel data1 (see Async Output Serial Interface).

Before reading out an asynchronous event through the JTAG interface, the following register bits have to be configured:

Bit

Configure to:

P2SM (p2s_mon_en)

0

JTGM (jtag_mon_en)

1

Operation steps:

send_ir(ASYNC_OUTPUT, 0x30, 8 bits)

data = 0xFF_FFFF
while data == 0xFF_FFFF:
   data = send_dr(0x00_0000, 24 bits)  # Receive async output message data

When the data read from the JTAG is different from 0xFF_FFFF, it can be interpreted as a valid async message.

11.6.3. Receiving Readout Events via JTAG

This operation is similar to the task of receiving asynchronous events.

The only difference is that whenever the READOUT command is issued to the JTAG, the chip will send out the information of the readout layer output as a 24-bit word padded with ‘0’: So for a fast consecutive attempts, might get the same data output that belongs to the same timestamp.

It is suggested to check the INTERRUPT pin behaviour too. After INTERRUPT rising edge the user should assert JTAG Readout command so that at the READOUT will work after each decision is done.

Readout layer data

0

0

0

Readout Layer Output (neuron output layer data) [20:0]

Operation steps:

  • Set P2SM (p2s_mon_en) = 0b0

  • Set JTGM (jtag_mon_en) = 0b1.

  • Wait for the INTERRUPT pin raising edge.

send_ir(READOUT, 0x31, 8 bits)

data = send_dr(0x00_0000, 24 bits)  # Receive async readout layer data
