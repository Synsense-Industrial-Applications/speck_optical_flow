Speck 2f

Speck 2f is a comprehensive, multicore spiking neural network processing chip capable of supporting large-scale spiking convolutional neural networks (SCNN) with a fully asynchronous chip architecture. It is fully configurable with the spiking neuron capacity of 0.32 million. Furthermore, it integrates a state-of-the-art dynamic vision sensor (DVS) that enables fully event-driven based, real-time, highly integrated solutions for varied dynamic visual scene.

Speck 2f can provide intelligence upon the scene at only milliwatts with a response latency in few milliseconds for classical applications, such as:

  • Event streaming classification

  • Pattern recognition

  • Smart device control, e.g. home appliance gesture control

  • Behavior detection* Event streaming classification

  • Pattern recognition

  • Smart device control, e.g. home appliance gesture control

  • Behavior detection

  • Security/safety monitoring to identify intruders or dangerous conditions.

  • Ultra-low power edge computing

Key Features

  • SPI master/slave interface for easy configuration

  • 1x internal DVS

  • 9x Convolutional (incl. pooling) layers

  • 1x Readout layer operating in average, max, max average, or threshold modes

  • Asynchronous serial interface

  • Ultra-low average working power consumption (~ 1 mW)

DVS Layer

  • 128 x 128 Pixel Array

  • Noise filter and hot pixel rejection

  • On only / Off only / Both / Merge filtering of DVS event polarity

  • Sum pooling 1:1, 1:2, 1:4

  • ROI selection

  • Mirroring in both X/Y

  • Rotate in 90-degree steps

  • Fanout of 2

CNN Layer

  • Max 9 convolutional processing layers

  • Max input dimension: 128x128

  • Max feature output size: 64x64

  • Max feature number: 1024

  • Weight resolution: 8 bit

  • Neuron state resolution: 16

  • Max kernel size: 16x16

  • Stride: {1, 2, 4, 8} independent in X/Y

  • Padding: [0..7] independent in X/Y

  • Pooling: 1:1, 1:2, 1:4

  • Fanout: 2

  • Leak operation on each layer

  • Spike decimator on each layer

  • Spike congestion balancer on each layer

  • Parallel computing on layer 0 and layer 1

Readout Layer

  • 15 classes and 1 idle class

  • Selectable moving average between 1, 6 and 32 time steps.

  • 4 readout modes: inactive/threshold/max spiking class/specific class.

  • 4 readout pins and 1 interrupt

How to Configure Chip

To configure the chip, the initial step is to acquire the configuration object for the Speck 2f. This can be accomplished using the following Python code:

1config = samna.speck2f.configuration.SpeckConfiguration()
2
3# modify config object
4
5# apply the configuration
6board.get_model().apply_configuration(config)

In subsequent sections, it is assumed that you have already obtained the configuration object config.

Note

In Speck 2f, numerous aspects can be monitored. However, merely enabling them as detailed below is insufficient for retrieving the output of the CNN layer in Python or visualizing it using the Visualizer. Please refer to Event Handling with Filter Graphs and Visualization.

DVS Layer (DVS Pre-Processing Layer)

The DVS Pre-Processing Layer monitoring can be enabled by setting config.dvs_layer.monitor_enable to True. The output event type is samna.speck2f.event.Spike with layer equals to 13.

The samna.speck2f.event.Spike.timestamp can store the timestamp that the chip emits it in microsecond, to enable the timestamp, please check Timestamp section.

In Samna Visualizer, events with polarity = 0 are visually represented in green, while events with polarity = 1 are shown in red. This color-coded visualization aids in quickly distinguishing between different polarities of DVS events.

By default, events originating from the internal sensor are NOT forwarded to the DVS Pre-Processing Layer, instead, they are simply discarded. This functionality is regulated by the attribute config.dvs_layer.pass_sensor_events. If either the config.dvs_layer.monitor_enable or the config.dvs_layer.raw_monitor_enable attribute is set to True, the config.dvs_layer.pass_sensor_events is automatically set to True.

Typically, if one intends to send DVS events to the pre-processing layer from an external source, the config.dvs_layer.pass_sensor_events attribute should be set to False.

Region of Interest

The region of interest (ROI) is configured using the coordinates of the top - left and bottom - right points. The top - left point coordinates are specified by config.dvs_layer.origin.x and config.dvs_layer.origin.y, while the bottom - right point coordinates are set by config.dvs_layer.cut.x and config.dvs_layer.cut.y.

By default, the top - left point is set to [0, 0], and the bottom - right point is set to [127, 127]. This default configuration corresponds to the full area coverage of the DVS sensor.

Mirroring

The DVS pre-processing layer supports mirror along the diagonal and thg x/y axis.

90 - degree clockwise Rotation:

1config.dvs_layer.mirror.y = True
2config.dvs_layer.mirror_diagonal = True

90 - degree counterclockwise Rotation:

1config.dvs_layer.mirror.x = True
2config.dvs_layer.mirror_diagonal = True

180 - degree Rotation:

1config.dvs_layer.mirror.x = True
2config.dvs_layer.mirror.y = True

For more details, please check samna.speck2f.configuration.DvsLayerConfig.mirror and samna.speck2f.configuration.DvsLayerConfig.mirror_diagonal.

Polarity Manipulation

By default, the DVS pre-processing layer yields DVS events with two polarities.

If you wish to merge the two polarities into a single value of 0, you can achieve this by setting the config.dvs_layer.merge <samna.speck2f.configuration.DvsLayerConfig.merge>` attribute to True.

Alternatively, you have the option to specify which polarity of events are allowed to pass through:

  • config.dvs_layer.on_channel: whether pass event with ON polarity. If enabled, the polarity of these events will also be set to 0.

  • config.dvs_layer.off_channel: whether pass event with OFF polarity. If enabled, the polarity of these events will also be set to 0.

Pooling

The DVS pre - processing layer additionally offers support for pooling. Pooling refers to the process of aggregating DVS events within a specific area. The available values for pooling are restricted to the set {1, 2, 4}.

You have the flexibility to independently configure the pooling values for the X and Y dimensions. The default values for the X and Y dimensions are set to (1, 1).

1config.dvs_layer.pooling.x = 1
2config.dvs_layer.pooling.y = 2

For more details, please check samna.speck2f.configuration.DvsLayerConfig.pooling.

Raw DVS Event Monitoring

One can also enable the RAW DVS events from the sensor by simply setting the attribute config.dvs_layer.raw_monitor_enable to True. Once this functionality is enabled, instances of the samna.speck2f.event.DvsEvent event are output. These events can also be visualized using the Samna Visualizer.

The samna.speck2f.event.DvsEvent.timestamp can store the timestamp that the chip emits it in microsecond, to enable the timestamp, please check Timestamp section.

Destination

The DVS pre-processing layer allows the user to configure two destinations:

1# enable the first destination
2config.dvs_layer.destination[0].enable = True
3# connect the DVS pre-processing layer output to the CNN layer 0
4config.dvs_layer.destination[0].layer = 0
5# enable the second destination
6config.dvs_layer.destination[1].enable = True
7# connect the DVS pre-processing layer output to the CNN layer 1
8config.dvs_layer.destination[1].layer = 1

DVS Filtering

The DVS Filter Block is included in the DVS pre-processing layer of Speck 2f in order to filter events depending on neighboring pixel (config.dvs_filter.filter_size.x, config.dvs_filter.filter_size.y) activity.

To activate the filter block, the first step is to set the attribute config.dvs_filter.enable to True. Additionally, a clock source for the filter must be specified, and there are two methods to accomplish this:

  1. Utilize a clock sourced externally. In the case of using the Speck 2f development kit, the FPGA slow clock module can be employed.

  2. Enable the internal slow clock of the Speck 2f for DVS filtering

    This can be done by setting config.dvs_filter.internal_slow_clk to True (default is False). The internally generated clock utilizes the random and continuous generation of internal DVS events (even though the generation frequency may fluctuate) by dividing the number of generated events by a constant (ranging from \(2^{14}\) to \(2^{17}\)). The exponent is set by config.factory_config.internal_slow_clk_divider (default is 17).

The filter block supports two MUTUALLY EXCLUSIVE modes: hot pixel filter mode and low-pass filter mode.

Hot Pixel filter Mode

This mode serves as the default one. It can be disabled via config.dvs_filter.hot_pixel_filter_enable. The filter forwards an event at position (x,y) if at least one pixel in the vicinity of (x,y) has spiked within a defined time window prior to the (x,y) event. The defined time window can be configured using config.dvs_filter.threshold.

Low-Pass Filter Mode

This mode is enabled through config.dvs_filter.low_pass_mode_enable.

In this mode, the filter works as a low-pass filter. This mode can be used to filter out 50/60 Hz light flickering noise produced by some lights such as fluorescent or LED lights that output a square wave with the frequency of the mains power supply.

When this mode is enabled, an event is passed only if no event in the neighboring pixels within the selected time window have spiked too close to the current event. The defined time window can be configured using config.dvs_filter.threshold.

CNN layers

Speck 2f has 9 CNN layers, each of which is controlled by config.cnn_layers:

1# get the first layer
2cnn = config.cnn_layers[0]

In common use cases, the configuration of network is set through Sinabs. Here are some configurations that are usually not set by Sinabs.

Parallel Computing Layers

Layer 0

Layer 0 implements a fully symmetric 2 parallel computation paths to improve throughput with respect to layer 3.

The parallelism is implemented in order to be almost fully transparent to the user, who can consider layers 0, 1 and 2 exactly the same in terms of interfaces and programmability.

Layer 0 differs from the other (regular) layers with the following characteristics:

  • 2 parallel convolutional cores, processing 1/2 of the input spikes each (2x speed improvement)

  • 2 copies of the same kernel sram, one for each convolutional core

  • 2 neuron updates at the same time when processing adjacent neuron addresses (best performance for even size kernels), with a best case 2x speed improvement

The expected performance increase in throughput is around 3.5x compared to the regular layers.

Two limitations of this parallel implementation are that:

  1. The order of the output spikes is not guaranteed. This issue also exists in regular layers, although with less variability.

  2. If a finite train of spikes is sent to the layer, it is not guaranteed that the last spike will be sent to the layer output. This is done to keep the implementation as simple and reliable as possible. Given issue (1), however, it is also not possible to predict what spike will be retained. When another spike is sent to the input of the layer, that should generate an output spike in the same data path, the retained spike will be ‘flushed’ out.

Layer 1

Layer 1 implements a partial parallelism in the data flow in order to improve throughput while limiting area utilization on chip.

The parallelism is implemented to be fully transparent to the user.

Layer 1 differs from the other (regular) layers with the following characteristics:

  • 2 kernel interfaces handling 1/2 of the kernel data each

  • 2 neuron updates at the same time when processing adjacent neuron addresses (best performance for even size kernels), with a best case 2x speed improvement

The performance of this implementation still has to be characterized in the lab.

Same as for layer 0, two limitations of this parallel implementation are that:

  1. The order of the output spikes is not guaranteed. This issue also exists in regular layers, although with less variability.

  2. If a finite train of spikes is sent to the layer, it is not guaranteed that the last spike will be sent to the layer output. This is done to keep the implementation as simple and reliable as possible. Given issue (1), however, it is also not possible to predict what spike will be retained. When another spike is sent to the input of the layer, that should generate an output spike in the same data path, the retained spike will be ‘flushed’ out.

Monitoring

Each CNN layer also supports monitoring its output as samna.speck2f.event.Spike with layer equals the layer index by enabling:

1cnn.monitor_enable = True

The samna.speck2f.event.Spike.timestamp can store the timestamp that the chip emits it in microsecond, to enable the timestamp, please check Timestamp section.

Input Congestion Balancer

In Speck 2f, each convolutional layer is equipped with a congestion balancer block at its data path input.

The congestion balancer enables dropping of input spikes at any time when the convolutional core of the layer is busy processing previous data. Specifically, if a train of spikes are sent to the layer, a number of them will be accepted (via some buffering) and the convolution computation starts. If, for example, the kernel is very large and a new spike arrives while the layer input is busy, this new spike will be dropped. As soon as the layer is again available, an incoming spike will be processed again.

This block is then able to adapt the spike input frequency to the convolution by capping it to the maximum that the layer can process.

This block can be enabled via cnn.input_congestion_balancer_enable (default False). When disabled, the block will let all spikes through.

Output Decimator

In Speck 2f, each convolutional layer is equipped with a decimator block at its data path output. The decimator block enables the user to reduce the spike rate at the output of a convolutional layer. When disabled, the block will let all spikes through. There are 8 levels that the user can set to control the spike rate (default is 1 spike passed every 2):

output_decimator_interval

Description

0

1 spike passed every 2

1

1 spike passed every 4

2

1 spike passed every 8

3

1 spike passed every 16

4

1 spike passed every 32

5

1 spike passed every 64

6

1 spike passed every 128

7

1 spike passed every 256

 
1# enable output decimator first
2cnn.output_decimator_enable = True
3
4# set 1 spike passed every 32
5cnn.output_decimator_interval = 4

Leak

Each layer includes a leak generation block, which will update all neuron values with provided leak values stored in a dedicated Leak SRAM: cnn.bias, which is a list of int16_t with length equals to the feature count.

The leak circuitry is enabled in a layer by its corresponding cnn.leak_enable.

In order to trigger the leak operation, a slow clock signal is need. Similar to DVS filter, there are two slow clock sources that a user can choose:

  1. Utilize a clock sourced externally. In the case of using the Speck 2f development kit, the FPGA slow clock module can be employed.

  2. Enable the internal slow clock of the Speck 2f for CNN leak

    This can be done by setting cnn.leak_internal_slow_clk_enable to True (default is False). The internally generated clock utilizes the random and continuous generation of internal DVS events (even though the generation frequency may fluctuate) by dividing the number of generated events by a constant (ranging from \(2^{14}\) to \(2^{17}\)). The exponent is set by config.factory_config.internal_slow_clk_divider (default is 17).

Destinations

If you are using Sinabs, it usually sets the destination. Here’s how to manually set the destinations for each layer.

Each CNN layer has two destinations. This means you can connect the output of each layer to two distinct destinations. For each destination, different values of pooling are available, which can be 1, 2, or 4, and feature number offset can be within the range [MIN_FEATURE - 1, MAX_FEATURE - 1].

The feature_shift shifts the feature number of features going to destination by N. It is important to configure this number correctly so that there is no overlap in feature space between inputs and outputs. When configuring take into account the feature space of each input for a layer and shift them so that they don’t overlap in the input of the destination layer.

 1# get the configure object of the CNN layer 0
 2cnn = config.cnn_layers[0]
 3
 4# enable the first destination
 5cnn.destinations[0].enable = True
 6
 7# connect the output to CNN layer 1
 8cnn.destinations[0].layer = 1
 9
10# set pooling to 1
11cnn.destinations[0].pooling = 1
12
13# set feature number offset to 10
14cnn.destinations[0].feature_shift = 10

Readout Layer

In Speck 2f, the readout layer serves as the post - processing layer. The main use of the post-processing block is to calculate the moving average over a time window for a maximum of 15 neurons, provide the maximum average of the 15 neurons and compare the value of the calculated moving averages against a specified threshold.

When an interrupt occurs and is correctly configured, the output results can be made readable via the 4 readout pins. By leveraging the readout pin monitoring feature offered by the development kit, it becomes feasible to validate your model in a manner closely approximating real-world application scenarios.

The readout pin monitoring feature can be enabled via Samna. To enable the readout layer, the config.readout.enable needs to be set to True first.

Slow clock Signal

A slow clk is needed, and we also have two options:

  1. Utilize a clock sourced externally. In the case of using the Speck 2f development kit, the FPGA slow clock module can be employed.

  2. Enable the internal slow clock of the Speck 2f for readout block

    This can be done by setting config.readout.internal_slow_clk to True (default is False). The internally generated clock utilizes the random and continuous generation of internal DVS events (even though the generation frequency may fluctuate) by dividing the number of generated events by a constant (ranging from \(2^{14}\) to \(2^{17}\)). The exponent is set by config.factory_config.internal_slow_clk_divider

Forward events to the readout block

To forward events to the readout block, simply set the destination layer to 12. It can be both from external events or internal events:

  1. Forward CNN layer events to the readout block

    1# Enable the first destination of a CNN layer and set its destination to the readout block
2cnn.enable = True
3cnn.destinations[0].layer = 12

  2. Forward DVS pre-processing layer events to the readout block

    1# enable the first dvs pre-processing layer destination and set its destination to the readout block
2config.dvs_layer.destinations[0].enable = True
3config.dvs_layer.destinations[0].layer = 12

  3. Forward external events to the readout block. A source node is necessary to send events to the Speck 2f, please check Sending Events to a Chip. The external events must be samna.speck2f.event.Spike with layer equals to 12.

    1# create a source node to inject events to the chip model
2source = samna.graph.source_to(board.get_model().get_sink_node())
3
4# send one spike event to the readout block
5source.write([samna.speck2f.event.Spike(layer=12)])

Configure the readout block

According to the CNN model, the user needs to set the addressing mode of the incoming spikes. There are 4 different addressing modes that could be selected through config.readout.readout_configuration_sel:

readout_configuration_sel

Description

0

2x*2y*4f

1

4x*4y*1f

2

2x*4y*2f

3

1x*1y*16f

The moving average of the output neurons is compared to the threshold value to produce an output if the received number of spikes is greater than the threshold set by config.readout.threshold ([0, 65535]).

The Speck 2f readout layer also provides a low pass filter. There are two selectable time windows, 16 (16 * slow clk period) and 32 (32 * slow clk period), which can be chosen by config.readout.low_pass_filter32_not16. The default value is False, which is 16 * slow clk period. The low pass filter is ENABLED BY DEFAULT, if you don’t want to use it, please set config.readout.low_pass_filter_disable to True.

Readout block output

To monitor the 4 readout pins, config.readout.readout_pin_monitor_enable needs to be set to True. If there is a valid result, an interrupt is generated by the chip and a samna.speck2f.event.ReadoutPinValue event is sent to Samna. The samna.speck2f.event.ReadoutPinValue contains 2 members, an index, indicating the feature, and a timestamp in microsecond, indicating when this event happened.

To receive events from the chip model, a sink node is necessary, please check Receiving Events from a Chip model.
